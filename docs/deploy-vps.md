# Deploying to a VPS (k3s)

The same three charts as local, installed with `values-prod.yaml` instead of
`values-local.yaml`. k3d *is* k3s in Docker, so the cluster on the VPS behaves
the same way: Traefik, the `local-path` storage class, and NetworkPolicy
enforcement (kube-router).

## What changes from local to prod

Everything else is identical: templates, probes, NetworkPolicies, the SSRF
guard and the security contexts.

| | local (`values-local.yaml`) | prod (`values-prod.yaml`) |
|---|---|---|
| Hostnames | `shop.127.0.0.1.nip.io`, `app.127.0.0.1.nip.io` | your domain: `shop.…`, `app.…` (DNS A records → VPS IP) |
| TLS | none (http) | cert-manager + Let's Encrypt (`infra/letsencrypt-issuer.yaml`); `COOKIE_SECURE` follows `ingress.tls.enabled` |
| Images | `urumi-registry:5000/*:dev`, `pullPolicy: Always` | `ghcr.io/<you>/*:<version>`, immutable tags, `IfNotPresent` |
| Secrets | generated by the charts on first install (`lookup` keeps them stable) | created by hand beforehand; charts use `existingSecret` |
| Upstream credentials | copied from the store/tools Secrets at install time | `platform-upstreams` Secret with keys `woo`, `fx`, `notes` |
| Storage | `local-path`, small volumes | `local-path` explicitly, bigger volumes (10Gi store DB + uploads, 5Gi Postgres) |
| Resources | defaults | MariaDB raised (256M buffer pool, 1Gi limit) |

## 1. Server

These steps assume Ubuntu 24.04 with at least 2 vCPU, 4 GB RAM and 40 GB disk
(the reference deploy uses a DigitalOcean 2 vCPU / 4 GB droplet).
- Open ports 22, 80 and 443 only. The k3s API (6443) stays closed; use it
  through an SSH tunnel.
- **Domain.** Either create DNS A records `shop.<domain>` and `app.<domain>`
  pointing at the server's IP, or skip DNS entirely and use
  `shop.<ip>.nip.io` / `app.<ip>.nip.io`, the same approach as local. Let's
  Encrypt issues certificates for nip.io names.

```bash
ufw allow 22/tcp; ufw allow 80/tcp; ufw allow 443/tcp
ufw allow from 10.42.0.0/16; ufw allow from 10.43.0.0/16   # pod and service CIDRs
ufw default deny incoming; ufw --force enable
curl -sfL https://get.k3s.io | sh -          # Traefik, local-path, NetworkPolicy controller included
sudo kubectl get nodes
# From your machine: copy /etc/rancher/k3s/k3s.yaml, then point it at an SSH tunnel:
#   ssh -N -L 6443:127.0.0.1:6443 root@<vps-ip> &
#   KUBECONFIG=~/.kube/urumi-vps.yaml kubectl get nodes
```

cert-manager (optional; without it, set `ingress.tls.enabled: false`):

```bash
helm repo add jetstack https://charts.jetstack.io
helm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace --set crds.enabled=true
kubectl apply -f infra/letsencrypt-issuer.yaml     # set your email first (or delete the line)
kubectl apply -f infra/traefik-https-redirect.yaml # http:// -> https:// (the session cookie is Secure)
```

cert-manager answers the HTTP-01 challenge with a short-lived solver pod in
the app's namespace. Default-deny would block it, so both charts add a
NetworkPolicy that lets Traefik reach it on 8089 when `ingress.tls.enabled`.

## 2. Images

```bash
echo "$GHCR_TOKEN" | docker login ghcr.io -u <you> --password-stdin
REGISTRY=ghcr.io/<you> TAG=0.1.0 scripts/build-images.sh
```

Either make the GHCR packages public, or create an `imagePullSecret`.
Then set `image.registry` and `image.tag` in the three `values-prod.yaml` files.

**Without a registry** (what the reference deploy does): build locally and
stream the images into k3s's containerd over SSH. With `pullPolicy:
IfNotPresent`, the kubelet uses them and never pulls.

```bash
TAG=0.1.0 scripts/build-images.sh                  # tags localhost:5000/<name>:0.1.0
docker save localhost:5000/{store-wordpress,woo-mcp,gateway,mcp-extra,dashboard}:0.1.0   | gzip -1 | ssh root@<vps-ip> 'gunzip | k3s ctr -n k8s.io images import -'
# then install with --set image.registry=localhost:5000 (and wooMcp/gateway/dashboard.image.registry)
```

## 3. Secrets (never in values or git)

```bash
kubectl create namespace store; kubectl create namespace tools; kubectl create namespace platform
r() { openssl rand -base64 33 | tr -d '/+=' | cut -c1-32; }

kubectl -n store create secret generic store-db --from-literal=root-password="$(r)" --from-literal=password="$(r)"
kubectl -n store create secret generic store-wordpress --from-literal=admin-password="$(r)" \
  $(for k in auth-key secure-auth-key logged-in-key nonce-key auth-salt secure-auth-salt logged-in-salt nonce-salt; do printf -- '--from-literal=%s=%s ' "$k" "$(r)$(r)"; done)
kubectl -n store create secret generic store-wc-api --from-literal=consumer-key="ck_$(openssl rand -hex 20)" --from-literal=consumer-secret="cs_$(openssl rand -hex 20)"
kubectl -n store create secret generic store-woo-mcp --from-literal=token="$(openssl rand -hex 24)"
kubectl -n tools create secret generic tools-fx --from-literal=token="$(openssl rand -hex 24)"
kubectl -n tools create secret generic tools-notes --from-literal=token="$(openssl rand -hex 24)"

kubectl -n platform create secret generic platform-gateway \
  --from-literal=encryption-key="$(openssl rand -base64 32)" --from-literal=admin-password="$(r)"
kubectl -n platform create secret generic platform-postgres --from-literal=password="$(r)"
kubectl -n platform create secret generic platform-upstreams \
  --from-literal=woo="$(kubectl -n store get secret store-woo-mcp -o jsonpath='{.data.token}' | base64 -d)" \
  --from-literal=fx="$(kubectl -n tools get secret tools-fx -o jsonpath='{.data.token}' | base64 -d)" \
  --from-literal=notes="$(kubectl -n tools get secret tools-notes -o jsonpath='{.data.token}' | base64 -d)"
kubectl -n platform create secret generic platform-llm --from-literal=groq-api-key=gsk_...
```

Back up `encryption-key` somewhere safe. Losing it means re-entering every
upstream credential that admins added through the dashboard.

## 4. Install (same order as local)

Per-server settings (hostnames, admin email, registry) go in a small override
file passed after `values-prod.yaml`, e.g. `-f my-vps.yaml` with
`ingress.host: app.<ip>.nip.io`.

```bash
helm upgrade --install store    charts/store    -n store    -f charts/store/values-prod.yaml    --wait --timeout 10m
helm upgrade --install tools    charts/tools    -n tools    -f charts/tools/values-prod.yaml    --wait
helm upgrade --install platform charts/platform -n platform -f charts/platform/values-prod.yaml --wait
```

## 5. Verify

```bash
node scripts/audit-workloads.mjs                      # probes, limits, non-root, default-deny, no exposed MCP
curl -sI https://shop.<domain>/ | head -1             # storefront over TLS
curl -s https://app.<domain>/healthz                  # gateway
curl -s -o /dev/null -w '%{http_code}\n' https://app.<domain>/mcp   # 401 without a key
GATEWAY_URL=https://app.<domain> SHOP_URL=https://shop.<domain> ADMIN_EMAIL=… ADMIN_PASSWORD=… \
  npm --prefix services/gateway run e2e
```

Upgrades use a new immutable tag: `helm upgrade … --set gateway.image.tag=0.1.1`.
Rollback is `helm rollback platform <revision>`. `scripts/upgrade-rollback-demo.sh`
runs the same sequence against the local cluster.
